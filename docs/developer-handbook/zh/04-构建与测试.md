# 4. 构建与测试

## 4.1 POM 层级与 CI 友好版本

```
microsphere-build:0.3.16        （外部父 POM——提供全部构建插件）
  └─ microsphere-spring          <version>${revision}</version>，<revision>0.2.40-SNAPSHOT</revision>
       ├─ microsphere-spring-parent / -dependencies / 各库模块（全部继承 ${revision}）
```

- 任何模块 POM 中都不得硬编码版本，由 reactor 统一传播 `${revision}`。
- `flatten-maven-plugin`（`flattenMode=resolveCiFriendliesOnly`，来自 `microsphere-build`）在发布时把
  `${revision}` 解析为真实版本。`.flattened-pom.xml` 是构建产物，已被 git 忽略。
- `java.version` 为 `17`（根 POM 覆盖祖父 POM 默认的 `8`）；`microsphere-build` 激活的 `java9+` profile 会设置
  `maven.compiler.release`，`java16+` 会为测试追加 `--add-opens` JVM 参数。
- `maven-compiler-plugin` 开启 `<parameters>true</parameters>`——注入点解析大量依赖参数名发现，此开关不可关闭。

## 4.3 Spring 兼容 Profiles

父 POM 用 profile 固定所测试的 Spring/Reactor 版本线，这是同一套代码服务 Spring 6.0 → 7.0 的机制：

| Profile | `spring-framework.version` | `reactor.version` | 默认激活 |
|---------|---------------------------|-------------------|----------|
| `spring-framework-6.0` | 6.0.23 | 2022.0.22 | 否 |
| `spring-framework-6.1` | 6.1.21 | 2023.0.19 | 否 |
| `spring-framework-6.2` | 6.2.18 | 2024.0.17 | 否 |
| `spring-framework-7.0` | 7.0.9 | 2025.0.7 | **是** |

```bash
# 针对指定 Spring 版本线构建/测试
./mvnw verify -P spring-framework-6.0
./mvnw verify -P spring-framework-7.0
```

**贡献者铁律**：你使用的任何 API 必须在 Spring 6.0.x 中存在，因为 CI 会跑完整矩阵
（3 个 JDK × 4 个 Spring profile = 12 种组合）。不得在无兜底方案的情况下依赖 Spring 7 独有 API。

## 4.4 常用命令

```bash
./mvnw verify                        # 完整构建 + 测试（默认 Spring 7.0）
./mvnw package -DskipTests           # 快速打包
./mvnw test -pl microsphere-spring-context              # 单模块测试
./mvnw verify -pl microsphere-spring-webmvc -am         # 单模块 + 其依赖
./mvnw test -pl microsphere-spring-context -Dtest=*PropertySource*   # 按模式匹配测试类
./mvnw install -DskipTests           # 安装到 ~/.m2 供下游本地项目使用
./mvnw javadoc:javadoc -pl microsphere-spring-context   # 本地生成 Javadoc

# 与 GitHub Actions 等价的 CI 调用
mvn --batch-mode --update-snapshots -Drevision=0.0.1-SNAPSHOT \
    test --activate-profiles test,coverage,spring-framework-7.0
```

`microsphere-build` 约定的测试规则：Surefire 包含 `**/*Test.java` 与 `**/*Tests.java`，排除
`**/Abstract*.java`（因此 `microsphere-spring-test` 中可复用的基类都以 `Abstract` 开头并标注 `@Disabled`）。
Checkstyle 仅在 `-Ptest` 下运行且默认跳过（`-Ddisable.checks=false` 可开启）；JaCoCo 在 `-Pcoverage` 下运行。

## 4.5 测试方式

- **框架**：JUnit 5 + Spring Test；可用 Mockito、Hamcrest、JSONassert。
- **优先使用内部测试工具**（`microsphere-spring-test`），不要手写上下文：

```java
// 启动一个原生注解上下文并断言
SpringTestUtils.testInSpringContainer(context -> {
    assertNotNull(context.getBean(MyService.class));
}, AppConfig.class);

// 内嵌数据库，用于 JDBC 测试
@EnableEmbeddedDatabase(dataSource = "testDataSource", type = EmbeddedDatabaseType.H2)
@Configuration
class DaoTestConfig {}

// 真实内嵌 Tomcat 的 Web 集成测试
@EmbeddedTomcatConfiguration(port = 8080, docBase = "classpath:/webapp")
class TomcatIT { }

// 注册中心类测试用的内嵌 ZooKeeper
@EmbeddedZookeeperServer(port = 2181)
class ZooKeeperIT { }
```

- **端点测试基类**：`AbstractWebMvcTest`（MockMvc）与 `AbstractWebFluxTest`（WebTestClient）已装配好
  `TestController` 与 `RouterFunctionTestConfig`；它们本身 `@Disabled`，继承后可直接调用提供的 `test*` 辅助方法
  或自行扩展。
- **请求态夹具**：`SpringTestWebUtils.createWebRequest(...)`、`MockServletWebRequest`、
  `WebTestUtils.mockServerWebExchange()`、`TestServletContext`（捕获 servlet/filter 注册）。
- **把测试当文档**：测试类名与被测类对应，测试方法名描述预期行为。阅读某模块的测试是理解其契约最快的方式。
- **覆盖率**：JaCoCo + Codecov，随 PR 上传。低覆盖类见
  [Codecov 面板](https://app.codecov.io/gh/microsphere-projects/microsphere-spring)。
