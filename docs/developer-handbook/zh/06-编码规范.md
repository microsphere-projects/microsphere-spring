# 6. 编码规范

## 6.1 源码格式与必需文件头

- 每个新增 `.java` 文件都必须带 **Apache 许可证头**。直接复制既有文件的开头块，例如
  `microsphere-spring-context/src/main/java/io/microsphere/spring/net/SpringProtocolURLStreamHandler.java`
  （context 模块 161 个主源码文件中有 148 个带此头，新文件必须遵循）。
- **类级 Javadoc** 需包含作者与版本标签——这是全库 261 个已文档化类型的一致约定：

```java
/**
 * <u>MyFeature</u> is ...
 *
 * @author <a href="mailto:mercyblitz@gmail.com">Mercy</a>
 * @since 1.0.0
 * @see SomeSpringClass
 */
```

  `@since` 使用所在分支的真实版本（`1.x` 线写 `1.0.0`，涉及 `0.2.x` 时写对应版本）。行文风格为 Spring 式、大量使用
  `{@link}`。
- 4 空格缩进、不用 Tab；import 顺序：先三方/Spring，再 `java.*`，最后静态导入。
- 仓库内无 `.editorconfig` 或格式化工具；Checkstyle 配置来自 `microsphere-build`
  （`-Ptest -Ddisable.checks=false` 运行）。

## 6.2 扩展范式（新功能必须遵循）

新能力一律以显式开启的注解暴露，绝不默认生效：

1. 在 `io.microsphere.spring.<领域>.annotation` 下定义 `@Enable<Xxx>`，标注
   `@Target(TYPE) @Retention(RUNTIME) @Documented`，并 `@Import` 一个**包级私有** registrar。
2. Registrar 继承 `AnnotatedBeanCapableImportBeanDefinitionRegistrar<Xxx>`（或
   `AnnotatedBeanCapableImportSelector`），从而免费获得 `BeanFactory`/`Environment` 能力与注解属性访问。
3. 提供熔断开关：尊重 `EnvironmentEnabled` 或 `microsphere.spring.<feature>.enabled` 属性，并对每一项注册决策打印
   TRACE 日志（参考 `WebFluxExtensionBeanDefinitionRegistrar` 的做法）。
4. 组合既有 `@Enable*` 时，以其作为元注解，并用 `@OverrideAnnotationAttributes` + `@AliasFor` 重新暴露与覆盖属性
   （见 `@EnableWebMvcExtension` → `@EnableWebExtension`）。
5. 对于运行时可能缺席的类，使用 `@ImportOptional`。
6. registrar/loader 保持内部化：注解才是公开契约，用户不应直接 import registrar。

## 6.3 命名与结构

- **对齐 Spring 包名**：扩展类放到与被其增强路径平行的包下——`io.microsphere.spring.core.env` ↔
  `org.springframework.core.env`，`io.microsphere.spring.beans.factory` ↔ `org.springframework.beans.factory`。
- **后缀承载语义**：`*Registrar`（ImportBeanDefinitionRegistrar）、`*Loader`（加载资源/属性源的 ImportSelector）、
  `*PostProcessor`（Bean(Body)FactoryPostProcessor）、`*Advice`/`*Interceptor`（横切钩子）、
  `*Resolver`/`*Factory`/`*Registry`（SPI 角色）、`*Utils`（声明为 `abstract` 且实现 `Utils` 的无状态静态工具）、
  `Adapter`（全 default 空实现的接口/基类）。
- **基础设施 Bean 名取类名小驼峰**，且通常暴露 `BEAN_NAME` 常量（`interceptingHandlerMethodProcessor`、
  `delegatingHandlerMethodAdvice`、`lazyCompositeHandlerInterceptor`、`ttlCacheResolver`、
  `configurationBeanBindingPostProcessor`）。保持该约定，用户才能按名覆盖。
- **属性名**写入各模块的 `constants/PropertyConstants`，带模块前缀（如 `microsphere.spring.webmvc.`），
  禁止内联字符串字面量。
- 优先继承/适配 Spring 类型而非替换；用 `ResolvableType` 解析泛型，而不是要求调用方传 `Class`。

## 6.4 依赖纪律

- 模块 POM 不写版本号——统一走父 POM 的 `dependencyManagement`/属性。
- 集成类依赖标 `optional`（p6spy、guice、zookeeper、tomcat-embed、spring-webflux），避免强加给使用者；
  并对路径做保护，缺失时优雅降级。
- SPI 注册写在 `META-INF/spring.factories`（本库仍使用 spring.factories，而非 `spring/*.imports`）；
  读取统一走 `SpringFactoriesLoaderUtils`（带缓存与自定义 ClassLoader 支持）。

## 6.5 兼容性底线

- `main`：Java 17 基线；Spring 最低支持 **6.0.x**——凡涉及 Spring API 用法，提 PR 前先用
  `-P spring-framework-6.0` 验证。命名空间为 Jakarta EE 11 / `jakarta.*`。
- `1.x`：Java 8 + Spring 4.3.x/5.3.x，`javax.*` 命名空间。需要同步的改动必须**手工回溯**
  （自动化只做 `main` → `dev`/`release`，不含 `main` → `1.x`）。

## 6.6 提交、测试与 PR

- 提交信息：简洁的祈使句主题行，如 `feat: add ...`、`fix: ...`、`refactor: ...`、`chore: bump ...`；
  发布自动化使用 `chore: bump version to next patch after publishing <rev>`。动手前先看
  `git log --oneline -20`。
- 任何行为变更必须附测试；本地至少跑 `./mvnw verify`，涉及 Spring API 时加跑
  `-P spring-framework-6.0`。
- PR 描述说明**动机**、关联 issue、注明已验证的 Spring 版本线；CI 绿了才进入评审；合入 `main` 后会自动传播到
  `dev` 与 `release`。
