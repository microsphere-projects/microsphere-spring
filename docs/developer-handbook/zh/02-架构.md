# 2. 架构

## 2.1 模块分层

仓库构建 9 个 Maven 模块。所有功能模块都继承 `microsphere-spring-parent`；三方版本集中在父 POM 与对外发布的 BOM
`microsphere-spring-dependencies` 中。

```
io.github.microsphere-projects:microsphere-build:0.3.16   （外部祖父 POM——提供全部构建插件）
 └─ microsphere-spring（根 pom.xml）                       （聚合工程，version = ${revision}）
     ├─ microsphere-spring-parent          版本对齐 POM：dependencyManagement + Spring 兼容 profiles
     ├─ microsphere-spring-dependencies    对外发布的 BOM：以 ${revision} 管理 7 个库构件
     ├─ microsphere-spring-context         核心扩展，其余模块全部构建在其上
     │   ├─ microsphere-spring-web         与传输层无关的 Web 抽象
     │   │   ├─ microsphere-spring-webmvc     Spring MVC（Servlet 栈）实现
     │   │   └─ microsphere-spring-webflux    Spring WebFlux（响应式栈）实现
     │   ├─ microsphere-spring-jdbc        P6Spy 集成
     │   ├─ microsphere-spring-guice       Google Guice 桥接
     │   └─ microsphere-spring-test        测试工具（依赖其余模块）
```

依赖关系要点：

- `context` 依赖 `microsphere-java`（核心工具）与 `microsphere-logging`；它是其他模块唯一的硬性内部依赖。
- `web` 只定义契约；**webmvc 与 webflux 是对称实现**，通过
  `io.microsphere.spring.web.util.SpringWebHelper` SPI 装配（各自模块的 `META-INF/spring.factories` 注册）。
- 重量级集成依赖均为 `optional`（p6spy、guice、zookeeper、tomcat-embed、spring-webflux……），使用者只会引入自己
  用到的功能。

## 2.2 包结构

基础包：`io.microsphere.spring.*`，包名与被增强的 Spring 原始包对齐：

| Microsphere 包 | 对应 / 用途 |
|----------------|-------------|
| `io.microsphere.spring.core.env` | 对应 `org.springframework.core.env`——可监听 environment、env 工具 |
| `io.microsphere.spring.config.env` | 属性源、YAML/JSON 工厂、env 事件 |
| `io.microsphere.spring.beans.factory[.annotation]` | 对应 `org.springframework.beans.factory`——DI 扩展、配置绑定、依赖图 |
| `io.microsphere.spring.context.annotation` | 注解驱动的 import 框架 |
| `io.microsphere.spring.context.event` | 事件/监听器扩展、Bean 生命周期事件 |
| `io.microsphere.spring.cache[.annotation]` | Spring Cache 的 TTL 扩展 |
| `io.microsphere.spring.net` | `spring:` URL 协议处理器 |
| `io.microsphere.spring.web.*` | Web 契约：`metadata`、`method.support`、`rule`、`event`、`util` |
| `io.microsphere.spring.webmvc.*`、`io.microsphere.spring.web.servlet.*` | Servlet/MVC 实现 |
| `io.microsphere.spring.webflux.*` | 响应式实现 |
| `io.microsphere.spring.jdbc.p6spy.*` | P6Spy 装配 |
| `io.microsphere.spring.guice.annotation` | Guice 桥接 |
| `io.microsphere.spring.test.*` | 按技术栈划分测试支持：`tomcat.embedded`、`jdbc.embedded`、`zookeeper.embedded`、`webmvc`、`webflux`、`util` |

## 2.3 `@Enable*` 扩展范式

这是本库每个功能都遵循的架构惯例，掌握它就能读懂整个代码库：

1. 公开的 `@Enable<Xxx>` 注解承载用户可见属性，并 `@Import` 一个**包级私有**的
   `ImportBeanDefinitionRegistrar`（注解是稳定 API，registrar 属于内部实现）。
2. Registrar 继承 `microsphere-spring-context` 提供的框架基类：
   `AnnotatedBeanCapableImportBeanDefinitionRegistrar<A>` / `AnnotatedBeanCapableImportSelector<A>`——天然获得
   `BeanFactory`/`Environment` 能力与注解属性访问。
3. `@OverrideAnnotationAttributes`（配合 `OverrideAnnotationAttributesStrategy`，默认实现
   `ConfigurationPropertyOverrideAnnotationAttributesStrategy`）允许派生注解覆盖元注解属性——
   `@EnableWebMvcExtension` / `@EnableWebFluxExtension` 正是借此通过 `@AliasFor` 重新暴露
   `@EnableWebExtension` 的属性。
4. `@ImportOptional` 可容忍 classpath 上缺失的类，保证可选依赖友好。
5. 熔断开关：registrar 尊重 `EnvironmentEnabled` 以及形如 `microsphere.spring.<feature>.enabled` 的属性
   （见 §2.4），不改代码即可关闭功能。

无需 `@Enable*` 的自动装配只发生在 `microsphere-spring-context` 的
`META-INF/spring.factories` `ApplicationContextInitializer` 条目，以及各模块的 SPI 条目
（如 `InjectionPointDependencyResolver`、`SpringWebHelper`、`WebEndpointMappingFactory`）中。

## 2.4 配置属性命名空间

所有运行时开关统一使用 `microsphere.spring.` 前缀（各模块 `*PropertyConstants` 类中定义常量）。重要属性：

| 属性 | 模块 | 用途 |
|------|------|------|
| `microsphere.spring.beans.auto-registered`（默认 `true`） | context | 关闭 `@EnableAutoRegistrationBean` 的自动注册 |
| `microsphere.spring.pre-instantiation.singletons.threads` / `.thread.name-prefix` | context | 并行预实例化线程池 |
| `microsphere.spring.listenable-autowire-candidate-resolver.enabled` | context | 启用可监听 `AutowireCandidateResolver` |
| `microsphere.spring.filter-mode` | context | 条件求值模式 `SEQUENTIAL` / `CONDITIONAL` |
| `microsphere.spring.configuration-property.repository.max-size` | context | `ConfigurationPropertyRepository` 缓存上限 |
| `microsphere.spring.context-initializer.<beanName>.enabled` | context | 逐个 initializer 的开关 |
| `microsphere.jdbc.p6spy.excluded-datasource-beans` | jdbc | P6Spy 包装时跳过的 DataSource |
| `microsphere.jdbc.p6spy.options.*` | jdbc | 通过 Spring `PropertySources` 提供 P6Spy 选项 |
| `microsphere.spring.webmvc.content-negotiation.*` | webmvc | 绑定到 `ContentNegotiationManagerFactoryBean` |
| `microsphere.spring.webmvc.view-resolver.exclusive-bean-name` | webmvc | 把视图解析限制为单个解析器 |
| `microsphere.spring.web.*` | web | Web 扩展开关 |

## 2.5 webmvc 与 webflux 如何共用 `web`

- `web` 定义：`WebEndpointMapping`（及 registry/resolver/factory/filter SPI）、拦截 SPI
  （`HandlerMethodInterceptor`、`HandlerMethodArgumentInterceptor`、`HandlerMethodAdvice`）、请求规则表达式
  （`WebRequestRule`、media/name-value 表达式）、事件，以及屏蔽请求访问差异的 `SpringWebHelper`。
- `@EnableWebExtension` 注册通用基础设施；各栈的 `@EnableWebMvcExtension` / `@EnableWebFluxExtension` 追加自己的
  registrar，注册本栈 resolver（`HandlerMappingWebEndpointMappingResolver`）、织入器
  （`InterceptingHandlerMethodProcessor`）以及可选组件（`ReversedProxyHandlerMapping`、body/返回值存储增强）。
- 运行期由 `WebRequestUtils` 分发到通过 `spring.factories` 发现的 `SpringWebMvcHelper` 或
  `SpringWebFluxHelper`；`UnknownSpringWebHelper` 是安全兜底。
